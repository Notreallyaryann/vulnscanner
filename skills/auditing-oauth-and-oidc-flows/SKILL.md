# Auditing OAuth and OIDC Flows

## Purpose
Inspect OAuth 2.0 and OpenID Connect authorization flows for security flaws including missing CSRF `state` parameter validation, open redirect vulnerabilities in `redirect_uri`, missing PKCE (Proof Key for Code Exchange) on public clients (SPAs / mobile apps), and token storage in insecure locations (`localStorage`).

## Safe operating rules
- Only test systems with authorization.
- Passively audit authorization URL parameters and client redirect configurations.
- Verify that `state` and `nonce` parameters are cryptographically random and verified on the callback.

## Workflow
1. Intercept or inspect the authorization redirect URL generated by the client application.
2. Check for the presence and entropy of the `state` parameter.
3. Check for PKCE parameters: `code_challenge` and `code_challenge_method=S256`.
4. Check if the client allows wildcard or relative `redirect_uri` destinations.

## Remediation Guidance
- Always mandate a cryptographically random, session-bound `state` parameter to prevent login CSRF.
- Implement PKCE (`S256`) for all Single-Page Applications (Next.js, React) and native applications.
- Enforce exact string matching for registered `redirect_uri` values in the identity provider.
- Store access tokens in memory or `HttpOnly; Secure; SameSite=Lax` cookies, not `localStorage`.
